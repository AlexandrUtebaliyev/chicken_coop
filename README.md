# Готовность марок — ВОМ

PWA (прогрессивное веб-приложение), которое **только читает** Google-таблицу
«Готовность_марок_ВОМ_журнал» и показывает готовность марок металлоконструкций
и комплектность по птичникам. В таблицу ничего не пишет.

Чистый HTML + CSS + JavaScript (ES-модули), без фреймворков и сборщика.

## 1. Локальный запуск (Windows)

Нужен любой простой HTTP-сервер — открывать `index.html` напрямую через `file://`
нельзя (ES-модули и service worker требуют `http://`).

PowerShell/cmd, из папки проекта:

```powershell
npx serve . -l 8080
```

или, если есть Python:

```powershell
python -m http.server 8080
```

Затем открыть в браузере: http://localhost:8080

## 2. Проверка расчётов

```powershell
node tests\check.mjs
```

Скрипт сверяет расчёты `model.js` с эталонными цифрами из PROMPT.md на снимке
таблицы `tests\fixtures\gotovnost_2026-10-18.csv`. Должен закончиться строкой
`=== Итог: N OK, 0 FAIL ===` и кодом выхода 0.

## 5. Как сменить таблицу или имена столбцов

Всё — в `config.js`:

- `SPREADSHEET_ID` — ID таблицы (часть ссылки между `/d/` и `/edit`).
- `SHEET_NAMES.readiness` / `SHEET_NAMES.journal` — названия листов
  «Готовность» и «Журнал».
- `READINESS_COLUMNS` / `JOURNAL_COLUMNS` — соответствие внутренних
  названий полей и заголовков столбцов в таблице. Для каждого поля можно
  указать несколько вариантов написания заголовка — первый найденный
  используется. Сопоставление идёт без учёта регистра, пробелов и
  знаков препинания.
- Столбцы птичников («Пт 1», «Пт 2», …) находятся автоматически по
  регулярному выражению в `model.js` (`findHouseColumns`) — их не нужно
  перечислять в конфиге, количество птичников не ограничено.

Таблица должна быть открыта по ссылке («Все, у кого есть ссылка — читатель»),
авторизация и API-ключи не используются.

### Состав марки (отдельная таблица)

Блок «Состав марки» на карточке марки читает ещё один документ — отдельную
Google-таблицу со спецификацией деталей (тоже только по ссылке, без API-ключей).
Настраивается через `SOSTAV_SPREADSHEET_ID` и `SOSTAV_COLUMNS` в `config.js`,
так же, как и основная таблица. В документе ожидается один лист со строками
двух типов («Сборка» — итог по марке, «Деталь» — один элемент состава),
сгруппированными по столбцу «Марка».

```

sw-register.js
service-worker.js      кэш оболочки приложения (cache-first)
manifest.webmanifest
icons/                 иконки PWA
drawings/              индексы чертежей «марка/деталь → ссылка на PDF» (см. ниже)
tests/check.mjs        проверка расчётов на снимке таблицы
tests/fixtures/        снимки CSV: «Готовность», «Журнал», «Состав марки»

```

## Экраны

- **Сводка** — плитки этапов, статусы, мини-ряд птичников, список групп
  (у каждой группы — количество шт по этапам: Изг/Покр/Гот/Отгр).
- **Марки** — поиск, фильтры по статусу/группе, сортировка. Числа на чипах
  статусов считаются по уже выбранной группе/поиску (не по всем 294 маркам) —
  например, после выбора группы в чипах видно, сколько марок именно этой
  группы в каждом статусе. Чипы показывают **фактическую активность по
  этапу** (например, «Отгружено» — сколько марок реально что-то отгрузили,
  а не только полностью отгруженные) — одна марка может подходить сразу под
  несколько чипов. В карточке марки в списке — заказано, все 4 этапа
  (Изг/Покр/Гот/Отгр) и цветная полоска.
- **Птичники** — список и карточка каждого птичника с недостающими марками,
  у каждой марки в списке — прогресс-полоска (есть/нужно).
- **Карточка марки** — кольцо готовности, этапы, веса, ссылка на чертёж марки,
  состав марки (детали со ссылками на чертежи, подгружается лениво),
  птичники, история из «Журнала» (тоже лениво).
- **Детали** — обратный поиск: список всех номеров деталей из состава с профилем,
  размерами и количеством марок, где деталь встречается (один и тот же номер
  детали часто используется в нескольких марках); карточка детали — чертёж
  и список марок, в состав которых она входит (переход на карточку марки).
  Есть поле «Птичников для расчёта» — своё число, не обязанное совпадать со
  столбцами «Пт N» в таблице (для планирования закупки на будущее расширение);
  по нему показывается, сколько штук детали нужно на 1 птичник и на всё
  заданное количество.

### Чертежи марок и деталей

Ссылки на чертежи (PDF на Google Диске) подгружаются из `drawings/assembly_index.json`
и `drawings/parts_index.json` — это заранее собранные статические индексы вида
`{ "К-1": { "viewUrl": "https://drive.google.com/file/d/.../view" } }`, они не
обновляются сами при изменении файлов на Диске. Если чертежи поменяются —
индексы нужно пересобрать заново (список файлов в папках Google Диска →
разбор имён файлов → запись json). На момент сборки: чертежи нашлись для
294 из 294 марок и для 273 из 338 номеров деталей, встречающихся в составе
(у остальных деталей ссылка на карточке просто не показывается).

Маршруты: `#/`, `#/marks`, `#/houses`, `#/house/<N>`, `#/mark/<марка>`,
`#/parts`, `#/part/<номер детали>`.
